# Codexy 产品战略

## 一句话

Codexy 是 Codex CLI 重度用户的移动行动层：把并行会话排好优先级，在真正需要
用户时发出可延续的提醒，并帮助用户把下一条 Prompt 发得更准确。

## 官方基线与差异化边界

OpenAI Codex Remote 已经覆盖手机连接桌面 Codex、继续或引导工作、审批动作、
查看输出以及切换主机和会话。Codexy 不在 MVP 中复制 diff、终端、完整审批和主机
管理。

Codexy 的窄切口是：

1. **CLI-first**：服务平时直接运行 Codex CLI、同时开多个终端的用户。
2. **行动分诊**：优先呈现需要决定、失败和可以接下一棒的会话。
3. **Prompt 工作流**：每会话独立草稿、发送前复核、Queue 默认、Steer 显式、
   未送达可撤回。
4. **项目记忆**：只用最近 10 条脱敏用户指令，整理目标、约束、决定、问题和建议
   下一条；每条结论可追溯来源。
5. **注意力友好通知**：默认不推 working；按会话延续通知；频率和语气由用户控制。

产品不宣称“全面优于官方 Remote”。更准确的承诺是：

> 对 CLI-first、多会话并行、希望少看手机但不漏掉关键接棒点的用户，Codexy
> 比通用远程控制更直接。

- <https://learn.chatgpt.com/docs/remote-connections>
- <https://learn.chatgpt.com/docs/notifications>

## P0 用户路径

1. 电脑运行一次 Codexy 安装器。
2. iPhone 扫码或打开私有 HTTPS 地址并添加到主屏幕。
3. 完成设备配对、启用通知并收到测试横幅。
4. 用户照常在不同项目目录运行 `codexy`。
5. 首页按行动优先级排列所有会话。
6. 点击横幅直达对应会话；可查看脱敏 Prompt、恢复思路或复核后发送下一条。

## 产品不变量

- `turn_finished` 只表示一轮回应结束，不表示项目完成。
- 看见通知不等于批准或解决 Codex 请求；真实状态只能由桌面端后续事件改变。
- 推送不得包含 Prompt、代码、路径、工具内容或疑似敏感信息。
- 思路整理只基于用户 Prompt，必须承认不知道助手实际完成了什么。
- 完整远程 Prompt 只短暂存在电脑端内存队列。
- App Server 永远只监听 loopback。

## P0 验收

- 8 个并行 CLI 中，所有 `needs_you` 会话都排在最前，并且不会因“我知道了”而消失。
- 同目录多个 CLI 仍能通过独立会话短码辨认。
- 三个会话分别输入草稿，来回切换后不串线、不丢失。
- Relay 离线时保留草稿、禁用发送且不显示成功。
- 默认通知在 20 次常规状态变化中不会产生 20 个横幅。
- 同一会话的后续通知延续覆盖，不同会话不互相覆盖。
- 点击通知打开正确会话。
- 10 条 Prompt 的约束、决定和显式问题能稳定分类并显示来源编号。

## P1（P0 稳定后）

- 全局待发箱：汇总草稿、等待发送、失败与重试。
- Focus Mode：只让一个主项目在限定时间内打断用户。
- 本机可选 AI 精炼：明确 opt-in，输出必须引用 Prompt 来源。
- 项目别名：用户可给同目录的多个 CLI 设置易辨认的本地名称。

## 明确不做

- 论文或资讯流、Todo、社交、广告、支付、归因和多租户账号系统。
- 信息不完整时的手机一键工具审批。
- 假完成百分比或“AI 已理解整个项目”等无证据文案。
- 复制官方 Remote 的终端、diff 和主机管理。
