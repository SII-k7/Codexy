# Codexy 产品战略

## 一句话

Codexy 是面向多个 CLI Agent 的移动注意力控制台：告诉用户哪里需要处理、Agent
做了什么、当前任务与挑战是什么，以及下一步最值得做什么。

## 四个必须立即回答的问题

工作台和会话页必须形成同一条决策链：

1. **哪里需要处理**：将等待决定、运行失败、中断、完成和本轮结束按人类介入价值排序，
   正在正常工作的 Agent 不抢占注意力。
2. **Agent 做了什么**：用户点击首页的“本机提炼”或打开会话页后，展示电脑本机生成
   的最近回复速览；首页不得静默批量读取完整回复，完整回复也不进入通知或持久状态。
3. **项目思路足够短**：将最近 10 条脱敏 Prompt 压缩为任务、挑战与下一步三项，
   每项最多两句话；原始 Prompt 默认折叠但仍可追溯。
4. **下一步最值得做什么**：结合会话状态和回复速览，给出一个最高优先动作与后续队列；
   所有建议都必须由用户复核。

## 官方基线与差异化边界

OpenAI Codex Remote 已经覆盖手机连接桌面 Codex、继续或引导工作、审批动作、
查看完整输出以及切换主机和会话。Codexy 不在 MVP 中复制 diff、终端、完整审批和
主机管理。

Codexy 的窄切口是：

1. **CLI-first**：服务平时直接运行 Codex CLI、同时开多个终端的用户。
2. **注意力队列**：优先呈现需要决定、失败和可以接下一棒的会话，并明确解释排序原因。
3. **Prompt 工作流**：每会话独立草稿、发送前复核、Queue 默认、Steer 显式、
   未送达可撤回。
4. **三段式项目简报**：只用最近 10 条脱敏用户指令，回答任务是什么、难点与挑战、
   接下来可能需要做什么，并生成一条需用户复核的下一步 Prompt。
5. **注意力友好通知**：默认不推 working；按会话延续通知；频率和语气由用户控制。
6. **回复速览**：按需读取最新一轮已结束的回复，在电脑本机过滤后提炼成结论、
   验证、注意事项与下一步；不把完整输出复制到手机状态或通知。
7. **会话控制台**：默认折叠为一行；展开后按会话读取电脑实时模型目录，调整模型
   与思考强度，并把状态、
   压缩、Review、停止映射为原生操作，而不是伪造 Slash Command Prompt。

产品不宣称“全面优于官方 Remote”。更准确的承诺是：

> 对 CLI-first、多会话并行、希望少看手机但不漏掉关键接棒点的用户，Codexy
> 比通用远程控制更直接。

## P0 用户路径

1. 电脑运行一次 Codexy 安装器。
2. iPhone 扫码或打开私有 HTTPS 地址并添加到主屏幕。
3. 完成设备配对、启用通知并收到测试横幅。
4. 用户照常在不同项目目录运行 `codexy`。
5. 首页生成一个跨项目注意力队列，并把最高价值动作置顶。
6. 点击横幅直达对应会话；可查看脱敏 Prompt、恢复思路或复核后发送下一条。
7. 会话页先给出最新一轮 Codex 回复速览；控制台默认折叠，需要时才展开调整下一轮
   配置或执行快捷控制。

## 产品不变量

- `turn_finished` 只表示一轮回应结束，不表示项目完成。
- 看见通知不等于批准或解决 Codex 请求；真实状态只能由桌面端后续事件改变。
- 推送不得包含 Prompt、代码、路径、工具内容或疑似敏感信息。
- 回复速览只读取最新一轮已结束的 `agentMessage`，优先使用最终回答；先在电脑本机
  过滤敏感内容，只返回结构化要点，完整回复不得推送或持久化。
- 思路整理只基于用户 Prompt，必须承认不知道助手实际完成了什么。
- 完整远程 Prompt 只短暂存在电脑端内存队列。
- 模型与思考强度只对所选会话的后续回合生效；破坏执行连续性的控制需要二次确认。
- 手机永远不获得原始 thread ID、工作目录或 App Server 网络入口。
- App Server 永远只监听 loopback。

## P0 验收

- 8 个并行 CLI 中，所有 `needs_you` 会话都排在最前，并且不会因“我知道了”而消失。
- `needs_you → failed → interrupted → completed/turn_finished` 的行动优先级稳定，
  正常 `working` 会话不进入待接棒数量。
- 首页最高优先动作同时显示“Agent 做了什么”和“你现在做什么”；初始使用生命周期
  摘要，只有用户点击本机提炼或已打开过该会话后才显示回复速览。
- 同目录多个 CLI 仍能通过独立会话短码辨认。
- 三个会话分别输入草稿，来回切换后不串线、不丢失。
- Relay 离线时保留草稿、禁用发送且不显示成功。
- 默认通知在 20 次常规状态变化中不会产生 20 个横幅。
- 同一会话的后续通知延续覆盖，不同会话不互相覆盖。
- 点击通知打开正确会话。
- 会话页先显示最新回复速览，控制台默认折叠；运行中仍展示上一轮已结束回复并明确
  标注“上一轮”。
- 回复速览最多 4 条要点，不泄漏代码、绝对路径、链接、邮箱或疑似密钥。
- 动态模型/强度选项与电脑端一致，配置确认后 `/status` 能读回；不支持的组合被拒绝。
- active 会话只开放停止，idle 会话才开放压缩与 Review；危险动作均需二次确认。
- 10 条 Prompt 能稳定压缩成任务、挑战与下一步三项，任何一项都不超过两句话；
  原始 P01–P10 默认折叠但可随时展开复核。
- 长按可隐藏普通会话轨道，并可逐条或全部恢复；隐藏不删除会话、不停止 Agent，
  `needs_you` 和 `failed` 仍进入顶部注意力队列。

## P1（P0 稳定后）

- 全局指令箱：汇总各轨道草稿、等待发送、失败与重试；与注意力队列保持分离。
- Focus Mode：只让一个主项目在限定时间内打断用户。
- 本机可选 AI 精炼：明确 opt-in，输出必须引用 Prompt 来源。
- 项目别名：用户可给同目录的多个 CLI 设置易辨认的本地名称。

## 明确不做

- 论文或资讯流、Todo、社交、广告、支付、归因和多租户账号系统。
- 信息不完整时的手机一键工具审批。
- 假完成百分比或“AI 已理解整个项目”等无证据文案。
- 复制官方 Remote 的终端、diff 和主机管理。
